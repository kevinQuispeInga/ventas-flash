# Modelo de datos

Los IDs relacionan documentos. Dinero: PEN, enteros en céntimos en Firestore/Functions; la UI convierte a S/. Fechas: Timestamp del servidor, nunca fechas aportadas por comprador. El catálogo tiene proyección pública de precio, líder y estado para escuchar una sola consulta. Las descripciones/imágenes son públicas; no publicar datos privados ahí.

## Estados de pago

`pending → payment_confirmed → payment_held → delivery_pending → receipt_confirmed → release_requested → completed`; `cancelled` reservado para un futuro flujo explícito de cancelación/reembolso. El proveedor DEMO registra las primeras transiciones juntas dentro de la compra y las últimas juntas al confirmar recepción. No existe acción para saltar estados arbitrariamente. No implementa pagos reales ni cancelaciones reales.

## Subastas y auto-puja

Incremento mínimo S/ 50, duración de publicaciones nuevas 3 minutos. Máximo 100 participantes por subasta para acotar lecturas y tiempo transaccional. Orden de ofertas: mayor máximo, luego prioridad temporal de primera participación, luego UID lexicográfico. La oferta manual compromete todo el importe; la automática alcanza el precio necesario para superar al segundo, sin exceder su máximo. Resolver requiere ordenar una lista acotada, sin bucles de pujas. Los máximos ya comprometidos no se reducen/cancelan. Los empates pagan el máximo empatado y gana la prioridad anterior.

Anti-robo: endAt nuevo = endAt vigente + 60 s si 0 < endAt - now <= 30 s. Un reintento con el mismo requestId devuelve el resultado anterior sin extender otra vez. Los auto-incrementos de una resolución no generan extensiones en cascada.

Scheduler procesa hasta 2,000 cierres por ejecución con páginas de 100. Los pendientes restantes se retoman al minuto siguiente; se requieren monitorización y ajuste de límites si crece el volumen. Dos ejecuciones concurrentes son seguras por revalidación transaccional. El endpoint closeAuctionNow permite recuperar cierre vencido desde UI y facilita pruebas; no admite hora/ganador del cliente. purchaseProduct también revalida plazo y ganador aunque Scheduler se retrase.

## Límites actuales

Catálogo e historial escuchan todos los registros de su consulta. Adecuado para esta fase; antes de gran escala incorporar paginación de mensajes/pujas/catálogo y búsqueda indexada. La compra inmediata cubre publicaciones normales/remates y liquidación del ganador de subasta; no hay precio «cómpralo ya» configurado que permita saltarse una subasta activa.
